# Windows 홈페이지 자동 업데이트

대상: 공개 저장소 AILAB-CBNU/ailab-site의 main 브랜치. 기존 Windows 무설치 서버의 Python을 사용하므로 Git 설치나 GitHub 로그인은 필요하지 않습니다.

## 설치

1. 업데이트 ZIP을 **기존 서버 프로젝트 폴더**에 덮어씁니다. `06-START-HTTPS-WEBSITE.bat`, `site`, `runtime`과 같은 위치에 11·12·13번 BAT 파일이 있어야 합니다.
2. 평소 서버를 실행하는 Windows 계정에서 `11-INSTALL-AUTO-UPDATE.bat`를 실행합니다. 현재 홈페이지를 즉시 업데이트한 뒤 작업 스케줄러를 등록합니다. `Installed`와 `DONE`을 확인합니다.
3. 이후 main에 올라온 홈페이지 변경을 5분마다 확인합니다. Windows 로그인 상태에서 실행되며 화면 잠금은 괜찮지만 로그아웃하면 작동하지 않습니다. 재부팅 후 같은 계정으로 로그인하면 다시 실행됩니다.

관리자 권한으로 실행할 필요는 없습니다. 학교 PC 정책으로 작업 등록이 거부되면 로그를 확인하고 해당 PC 관리자에게 작업 스케줄러 등록 권한을 요청하십시오. 로그인 없이 실행하려면 Windows 서비스 계정/암호를 이용하는 별도 설정이 필요합니다.

## 버튼

- 11번: 즉시 업데이트하고 자동 실행 등록 (다시 실행해도 중복 등록되지 않음).
- 12번: 수동으로 즉시 확인/업데이트.
- 13번: 자동 실행 등록 해제. 현재 홈페이지와 서버는 유지.

## 반영 범위

`site/` 전체만 교체합니다. GitHub에서 삭제된 홈페이지 파일도 반영됩니다. `.env`, 세미나 파일/목록, 관리자 인증·편집값, 봇 설정, 인증서, runtime, 서버 프로그램은 변경하지 않습니다. Python 서버와 Caddy 재시작 없이 홈페이지 파일을 제공합니다. 파일 교체 시점에는 극히 짧은 요청 실패가 생길 수 있습니다. GitHub main에 쓰기 권한이 있는 사람은 실제 공개 홈페이지의 내용을 바꿀 수 있으므로 검토한 변경만 main에 반영하십시오.

다운로드를 완료하고 필수 파일을 확인한 다음 폴더를 교체합니다. 다운로드/검증 실패 시 기존 사이트를 유지하고, 교체 실패 시 원래 폴더로 복원합니다. 같은 커밋은 다시 적용하지 않습니다. 네트워크 오류/API 한도 초과 시 다음 예약 시간에 다시 시도합니다. 자동 업데이트 프로그램 자체는 자동 교체하지 않습니다.

관리자 편집값은 유지되므로 GitHub의 텍스트보다 우선 적용될 수 있습니다. 목록 순서가 바뀐 페이지는 이전 위치 기반 편집값이 다른 항목에 적용되지 않았는지 미리보기로 확인하십시오.

## 로그와 복구

- 로그: `logs/website-update.log` (1 MB마다 회전, 이전 2개 유지)
- 백업: `website-update-state/backup-날짜시간/` (최근 3개)
- 적용 커밋: `website-update-state/deployed-commit.txt`

복원할 때는 13번으로 자동 업데이트를 중단한 뒤 백업 폴더 전체를 `site` 폴더로 복사합니다. 다시 자동 업데이트를 켜면 GitHub의 현재 버전이 적용될 수 있으므로 필요한 경우 GitHub에서도 해당 변경을 되돌립니다. 설치 폴더를 이동하기 전 13번으로 기존 작업을 해제하고 이동 후 11번을 다시 실행하십시오.

## 배포 파일 생성

`python scripts/build_windows_portable.py`의 전체 ZIP에도 11·12·13번이 포함됩니다. 홈페이지 자동 업데이트는 최초 서버 구축, 포트 개방, HTTPS 설정, 서버 프로세스 자동 시작을 대신하지 않습니다.
