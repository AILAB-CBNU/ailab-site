# 연구실 아침 브리핑

기존 AI Lab Seminar 봇에 추가되는 기능입니다. Windows 무설치 Python에서 동작하며 OpenAI Responses API를 직접 호출합니다. 이번 기능의 실행 엔진은 Hermes가 아닙니다. 기존 홈페이지·세미나 실행 방식을 유지하면서 하나의 봇 프로세스로 운영합니다.

## 서버 PC 적용

1. 기존 `06`, `10` 창을 닫고 `ailab-briefing-update-20260923.zip`을 압축 해제합니다.
2. 안의 폴더와 `14-SETUP-LAB-BRIEFING.bat`를 **기존 06 BAT 파일 옆**에 덮어씁니다. 기존 데이터·설정 폴더는 삭제하지 않습니다. 이전 과제·갤러리·사진 수정도 포함됩니다.
3. `14-SETUP-LAB-BRIEFING.bat`를 실행합니다.
4. 라운지 ID 기본값은 `1551783879235600540`입니다. 생성해 둔 `☀️・아침-브리핑` 채널 ID는 `1552229147022065664`입니다. 빈칸은 기존 `lab-briefing` 또는 `☀️・아침-브리핑` 채널을 찾고, 없으면 확인 후 생성합니다. 자동 생성에는 봇의 채널 관리 권한이 필요합니다. 수동으로 채널을 만들고 ID를 입력하면 그 권한은 필요 없습니다.
5. 서버에 API 키가 없으면 숨김 입력창이 나옵니다. 직접 입력한 키는 서버 프로젝트의 `.env.local`에만 저장합니다. 현재 개발 PC에 저장된 키는 ZIP에 포함되지 않으므로 **서버에서도 한 번 설정**해야 합니다. 기존 `.env.local`이 있으면 재사용합니다.
6. 모델은 기본 `gpt-5.6-luna`입니다. 아주 짧은 가상 입력으로 모델 호출을 확인합니다. 설정 과정에서 실제 대화를 OpenAI에 보내지 않습니다.
7. `06`과 `10`을 다시 실행하고 켜둡니다. **처음 설정한 날의 대화부터, 다음 날 오전 9시** 브리핑합니다. 로그에 `Lab briefings enabled: 09:00 Asia/Seoul`이 표시돼야 합니다.

프로젝트의 `.env.local`과 `discord-sync-state/`는 Git·배포 ZIP 제외 대상입니다. 키를 채팅, 공지, GitHub에 올리지 마세요. 비용은 선택한 조직의 API 사용량으로 청구됩니다.

## 구성원 사용법

- 평소 `💬・연구실-라운지`에서 대화합니다. 다른 채널·DM·첨부파일 내용은 수집하지 않습니다. 스레드 답글도 이 버전에서는 수집하지 않습니다.
- 개인에게 업무를 맡길 때는 **실제 Discord @멘션**을 사용하세요. 예: `@전종훈 9월 25일까지 실험 결과 표를 정리해 주세요.` 이름만 쓰거나 담당자가 불명확하면 개인에게 잘못 보내지 않도록 확인 항목으로 남깁니다.
- 자신이 맡을 때는 `제가 내일까지 실험 결과를 정리하겠습니다`처럼 명확히 씁니다. 상대 날짜는 메시지 작성 시점의 한국 시간으로 해석합니다.
- `매주`, `매월` 같은 반복 일정은 개별 날짜를 명시해 주세요. 외부 캘린더 연동 및 반복 일정 자동 생성은 포함하지 않습니다.
- 공통 채널에는 전날 공동 논의와 미완료 공동 일정, 원문 링크를 올립니다. 개인별 업무 목록은 DM으로 보냅니다.
- **내 할 일** 버튼은 누른 본인의 목록만 비공개로 보여줍니다. 완료/제외하면 다음 리마인드에서 빠집니다. DM 차단 시 공통 채널의 이 버튼을 이용하세요. 개인 정보는 공통 채널에 대체 게시하지 않습니다.
- 공동 일정은 **공동 일정 관리** 버튼에서 서버 관리자(서버 관리 또는 관리자 권한)가 완료/제외합니다. 지난 일정도 완료 처리 전에는 남으므로 놓친 항목을 확인할 수 있습니다.
- AI 정리가 잘못됐으면 해당 항목을 제외하고 라운지에 올바른 일정/담당자를 명확히 남깁니다. 원문 링크를 함께 확인하세요.
- 본인이 원문 대화에서 명확히 완료/취소했다고 말한 개인 업무는 다음 브리핑 때 반영할 수 있습니다. 애매한 완료는 추정하지 않습니다. 날짜 수정·반복 일정은 자동 추적하지 않습니다.

## 운영 및 제한

- 시간대는 Windows 설정과 무관하게 고정 **KST(UTC+9)**, 매일 09:00 이후 30초 이내입니다. 요약 생성 시간만큼 발송은 늦어질 수 있습니다.
- 서버/10번 창이 꺼져 있으면 발송하지 못합니다. 당일 09:00 이후 재실행하면 전날 브리핑을 보완하지만, 여러 날 꺼져 있었던 기간 전체를 자동 소급하지 않습니다.
- 원문 전체는 디스크에 저장하지 않습니다. 요약·업무·발송 상태는 `discord-sync-state/briefings/ledger.json`에 저장됩니다. 최근 브리핑은 30일, 업무 이력은 로컬에 유지합니다. 홈페이지에서는 제공하지 않습니다.
- 하루 최대 10만 글자·페이지 100개, 한 번에 16,000자 단위로 요약합니다. 범위를 넘으면 일부만 요약해 전체인 것처럼 게시하지 않고 실패 로그를 남깁니다. 미완료 업무 200건을 넘으면 먼저 완료/제외로 정리해야 합니다.
- AI 준비 실패는 30분 간격, 하루 최대 3회입니다. 요청량을 제한하지만 금액 상한을 보장하지는 않습니다. 조직의 API 예산도 별도로 관리하세요.
- 발송은 기록을 저장하며 단계별로 진행합니다. 네트워크 오류로 발송 여부가 불확실하면 최근 메시지를 확인하고, 확인할 수 없을 때는 중복 발송 대신 멈춥니다. `Uncertain Discord delivery`가 나타나면 해당 날짜의 실제 메시지와 ledger의 `inflight` 항목을 확인해야 합니다. ledger를 무작정 삭제하면 이미 보낸 내용을 다시 보낼 수 있습니다.
- Discord 봇 권한: 원본 채널 보기·기록 읽기, 브리핑 채널 보기·메시지 보내기. 기존 Message Content Intent가 필요합니다. 수집 채널 ID는 설정된 한 채널로 제한합니다.
- 수집 대상 라운지 구성원이 볼 수 있는 채널에만 요약을 게시하세요. 설정은 두 채널의 권한 덮어쓰기가 다르면 확인을 요구합니다. 이후 채널 권한이 바뀌면 전송을 중지하므로 14번 설정에서 새 노출 범위를 확인해야 합니다.
- 끄려면 10번 창을 닫고 `discord-sync-state/briefing-config.json`의 `enabled`를 `false`로 변경한 뒤 10번을 다시 켭니다. 세미나 수집만 계속됩니다.

## Hermes를 별도로 사용할 때

Hermes의 공식 Windows 가이드는 네이티브 설치를 지원합니다. 과거 Docker/Hyper-V 문제와는 별개이며, 이 업데이트는 Hermes를 자동 설치하지 않습니다.

서버 PC에서 Hermes까지 대화형 연구 도우미로 쓰려면 공식 설치 가이드의 Windows 설치 절차를 따르고, Hermes 설정에서 OpenAI 제공업체와 모델을 선택하세요. 현재 봇과 Hermes의 Discord Gateway를 같은 토큰으로 동시에 켜지 마세요. Hermes용 별도 봇을 사용하거나 기존 봇 중 하나가 연결을 전담하도록 해야 합니다. 이 브리핑은 10번이 예약을 담당하므로 Hermes에 같은 오전 9시 작업을 중복 등록하지 않습니다.
